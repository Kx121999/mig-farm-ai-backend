أهم التطويرات:
1. Sales Conversation OS V17
   - تحليل نية الرسالة الحالية على مستوى المحادثة وليس الكلمات فقط.
   - أوضاع: social / direct_fact / recommend / compare / objection / technical / project / close / conversation.
   - يحدد سبب الاعتراض: السعر، الثقة، الملاءمة، التوفر، الوقت، التعقيد، أو الخوف من المخاطرة.
   - Buyer Readiness داخلي لمعرفة هل العميل يتصفح أم يقارن أم قريب من الشراء.
   - Next Best Action لكل رسالة بدلاً من CTA ثابت.

2. Adaptive Response Shapes
   - يختار شكل رد مناسب لكل رسالة.
   - يتجنب تكرار نفس شكل الرد السابق.
   - لا يحول الرسائل القصيرة إلى تقارير.
   - لا يستخدم القوائم إلا عندما تكون مفيدة فعلاً.

3. History-aware Follow-ups
   - يمرر آخر 8 أدوار محادثة موثوقة للعقل العصبي.
   - يفهم: التاني؟ طب الأرخص؟ لا قصدي خيار؟ خلاص هاخد اتنين.
   - يمنع تكرار أسئلة سبق أن أجاب عنها العميل.

4. Question Budget
   - بعض الرسائل لها 0 أسئلة متابعة إذا كانت الإجابة وحدها كافية.
   - الحالات التي تحتاج تأهيل فعلي يسمح فيها بسؤال واحد فقط.

5. Objection Root-Cause Engine
   - لا يعالج "غالي" بنفس رد "مش مقتنع".
   - السعر → بديل/قيمة موثقة.
   - الثقة → دليل.
   - التوفر → تحقق حي وبديل.
   - الملاءمة → متغير واحد يحسم الاختيار.
   - المخاطرة → إرشاد موثق.

6. Naturalness Quality Gate
   - يرصد البداية القالبية.
   - يرصد الرد الطويل على رسالة قصيرة.
   - يرصد كثرة الأسئلة.
   - يرصد البيع غير المطلوب.
   - يرصد التكرار مع آخر ردود المساعد باستخدام n-gram overlap.
   - يرصد الـCTA والندرة/الاستعجال غير الموثقين.

7. Bounded Naturalizer Retry
   - إذا الرد جيد معلوماتياً لكنه روبوتي أو متكرر، يسمح بإعادة صياغة واحدة فقط.
   - ممنوع تغيير اسم منتج أو سعر أو عملة أو توفر أو حقيقة تقنية أو قانونية.
   - بعد إعادة الصياغة يتم تشغيل Commerce Verification مرة أخرى.

8. Sales Safety
   - ممنوع اختراع خصم أو عرض أو ندرة أو "آخر كمية" أو ضمان أو تقييم عملاء.
   - لا يتم دفع المنتج في الكلام الاجتماعي أو التشخيص الفني إذا العميل لم يطلب منتجاً.
   - الإغلاق Soft Close طبيعي حسب المرحلة وليس واتساب إجباري.
